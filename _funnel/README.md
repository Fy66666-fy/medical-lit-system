# 内测推广 · 四级漏斗

**四级**：曝光 → 落地页访问 → 加入频道 → 次周活跃

工具链：`collect.py` 录入 → `funnel.csv` / `funnel_total.csv` 存数据 → `report.py` 出看板（`report.html`，零依赖自包含）。

---

## 一、四级定义与数据源

| 级 | 名称 | 定义（口径） | 数据源 | 能拆到渠道？ |
|---|---|---|---|---|
| **L1** | 曝光 | 内容被展示的次数。取各渠道后台口径：丁香园=帖子阅读数，知乎=文章/回答浏览数，B站=播放量，小红书=浏览数。同一内容多次改稿**不重复计**，只记当周增量 | 各渠道创作者后台，每周抄一次 | ✅ 能 |
| **L2** | 落地页访问 | 打开落地页的**独立访客数（UV）**，同一访客当天多次打开只算 1 次 | 落地页统计（见第三节） | ✅ 能（靠 `?f=` 参数） |
| **L3** | 加入频道 | 当周腾讯频道**成员净增**（周末成员数 − 上周末成员数） | 频道资料页成员数，每周记一次 | ❌ 不能 |
| **L4** | 次周活跃 | 上周加入的人里，本周在频道**发过言**或**用过产品**的去重人数 | 频道发言名单 + 在线版（可选） | ❌ 不能 |

### 为什么 L3/L4 拆不到渠道

所有人扫的是**同一个腾讯频道二维码**，平台不回传来源，所以入群这级只能看总数。

要拆渠道只有两个办法，都不完美，按需取用：

1. **入群问一句**：在频道欢迎语/置顶里问"从哪里看到我们的？"，靠自觉回答，**覆盖率通常不到 30%**，只能当定性参考，不要拿它算转化率；
2. **分渠道投不同内容、错开时间**：同一周只在 A 渠道发，看当周入群增量，用时间切片反推。样本小、噪声大，仅供粗判。

**结论**：渠道优劣就看到 L1→L2 为止（哪条内容能把人引到落地页），L2→L3 之后只看总体。别硬凑一个拆不到渠道的数字。

## 二、四个转化率怎么读

| 指标 | 公式 | 反映什么 | 经验阈值 |
|---|---|---|---|
| **点击率** | L2 / L1 | 内容钩子 + 人群是否对路 | 内容型渠道 1%–5% 算正常；< 0.5% 说明选题或渠道错配 |
| **入群率** | L3 / L2 | 落地页有没有把价值讲清楚 | 内测招募 5%–15%；< 3% 说明"为什么要加群"没讲明白 |
| **留存率** | L4 / L3 | 产品首用体验 + 频道有没有内容 | ≥ 20% 算健康；< 10% 要么产品没跑通，要么频道是死群 |
| **总转化率** | L3 / L1 | **渠道质量的最终判据**，用来决定加码还是砍掉 | 内测期 0.05%–0.5%，低于此量级优先换渠道 |

用法：**每周只看总转化率排渠道**，把下周的精力挪到前两名。前三级各自用来定位"卡在哪一环"。

## 三、L2（落地页访问）数据源 —— 三条路

> ⚠️ **隐私红线先说在前面**：README 的隐私条款白纸黑字写着
> **"不做用户画像与行为追踪；不接入广告与统计 SDK"**。
> 这是本项目对医学用户的核心承诺，**任何第三方统计（GA / 百度统计 / 51.la / 不蒜子）都不能直接往落地页里塞**。
> 下面三条路，只有 A 和 B 与这条承诺不冲突。

### A. 人工填报（当前默认，零依赖）

去各渠道后台抄数，L2 这一级**如果没接任何统计就填渠道给的外链点击数**；渠道不提供（知乎、丁香园都不提供外链点击）就**留空并在 note 里写明来源**。

诚实原则：**宁可空着，也不要编一个数填进去**。空值在报表里显示为「—」，不会污染转化率计算。

### B. 自建匿名计数（推荐，符合隐私承诺）

`counter_server.py` 是一个不到 100 行的极简计数服务，设计上刻意做到：

- **不存 IP、不存 UA、不设 cookie、不做任何指纹**；
- 只维护「日期 → 渠道 → 计数」这一个聚合整数表；
- 当日去重用的哈希**只在内存里活 24 小时，不落盘**；
- 前端只发一个 `GET /hit?f=丁香园`，页面不被阻塞，失败静默。

部署后把端点 URL 填进 `sources.json` 的 `counter_url`，`collect.py --auto` 会自动拉取每周 UV。**部署前需要你确认**——它会让落地页多一个外部请求。

### C. 接 Umami Cloud（不推荐，需改隐私条款）

Umami 无 cookie、不采集个人信息，合规上比 GA 好得多。但它仍是"统计 SDK"，且会采集 referrer / 页面路径。

要走这条路，**必须先改 README 与落地页的隐私表述**（把"不接入统计 SDK"改成"仅接入无 cookie 的聚合统计，不采集身份信息、不做行为追踪"），并同步应用内「隐私与数据」页的条款与生效日期。**没有你的明确同意，我不会做这个改动。**

## 四、每周怎么跑（约 5 分钟）

```bash
# 1) 录渠道数据（交互问答，回车跳过不知道的）
python _funnel/collect.py --week 2026-W41

# 也可以命令行直接写
python _funnel/collect.py --week 2026-W41 --set 丁香园 impressions=5200 landing_uv=210

# 2) 录全站总量（成员数、次周活跃）
python _funnel/collect.py --week 2026-W41 --total joins=12 active=5 members=47

# 3) 出看板
python _funnel/report.py          # 生成 report.html，双击打开

# 想先看漏斗长什么样（用示例数据，不是真实数据）
python _funnel/report.py --demo   # 生成 demo_report.html
```

周编号用 **ISO 周（周一为一周之始）**，格式 `2026-W41`。不传 `--week` 默认取上一周。

数据文件（真实数据，入仓）：

- `funnel.csv`：渠道级，列 `week, channel, impressions, landing_uv, note`
- `funnel_total.csv`：周级，列 `week, members_end, joins, active_next_week, note`

两者都是 UTF-8，改完直接 commit。同 `week + channel` 重复录入会**覆盖**（幂等），不怕补录。

示例数据（仅供演示，**别往里录**）：`example_funnel.csv` / `example_funnel_total.csv`，
配合 `report.py --demo` 生成 `demo_report.html`，用于确认漏斗和看板长什么样。

生成产物（`report.html` / `demo_report.html` / `counter_data.json` / `sources.json`）
已在 `.gitignore` 中排除，不入仓。

## 五、冷启动期怎么办

前两周数字大概率是个位数甚至 0，这是正常的，**不要因为数字小就改口径**。

前四周只做三件事：

1. 每周固定时间记一次，**别断**（断了就没法看趋势）；
2. 记录时顺手在 `note` 里写"这周发了什么"，四周后回头看哪类内容带来的人最多；
3. **累计 L3 到 30 人以上再看留存率**——样本小于 30 时 L4/L3 的波动主要是噪声，看它做决策容易误判。
